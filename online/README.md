# 星星学习工作台 · 联网多小朋友版

React/Vite 前端、Node.js/Express API、生产 PostgreSQL；本机开发使用持久化 PGlite。每位家长使用邮箱和验证码登录，不创建孩子账号；首次登录自动创建家庭。支持最多 20 位小朋友：一个直接进入，多个在登录后选择，并可在工作台切换或添加。每位小朋友有独立资料、任务、打卡、积分和兑换；家庭共用商品和有限库存。家长选择小朋友后操作该工作台，兑换与共享库存同一数据库事务提交。

## 本机启动

安装 Node.js 22 或 24，在本目录运行：

```powershell
npm ci
npm run build
npm run local
```

打开 http://127.0.0.1:3000 ，输入测试邮箱，点击获取验证码。**本机测试模式不会发送真实邮件，验证码仅显示在启动服务的终端**；输入验证码登录。60 秒重发间隔、5 分钟有效期和最多 5 次错误尝试。生产环境禁止使用控制台邮件模式。退出服务按 `Ctrl+C`；如果之前版本仍在运行，先关闭旧进程再启动新版。

本机数据保存在 `.local-db/`，不要随意删除；这不是生产数据库。如需使用真实 PostgreSQL，按 `.env.example` 设置 `DATABASE_URL` 后运行 `npm run dev`。`npm test` 执行测试。暂不支持邮箱换绑或账号注销。

## 备份与旧版本迁移

家长管理中的“导出备份”包含本家庭所有小朋友、共享商品和库存；导入完整家庭备份将替换该家庭所有业务数据，先分别备份两边。旧单文件导出的 version 1 备份只允许在家庭已有且仅有一位小朋友时导入，替换该孩子数据和家庭商品，避免影响其他孩子。邮箱账号和登录会话不包含在备份中。

旧的账号密码联网版数据仍留在原数据库。使用邮箱登录并且新家庭尚无小朋友时，可在添加小朋友页面展开“迁移旧家长账号”，填写原家长用户名及密码；系统复制旧任务、积分、打卡、商品和兑换为第一位小朋友，旧数据不会删除。迁移之前先用旧版本导出备份。若已添加小朋友，不支持此自动迁移；请先备份数据后再制定人工迁移方案。旧孩子账号不能登录新版。

## 腾讯云邮件推送接入

生产环境使用腾讯云邮件推送 API，不依赖 SMTP。开通邮件推送并完成实名认证，添加自己控制的发信域名，按照控制台指引配置并验证 DNS，创建发信地址，以及包含 `{{code}}` 变量的验证码模板。模板示例：`你的登录验证码为 {{code}}，5 分钟内有效。` 配置模板需通过腾讯云审核，具体以控制台要求为准。创建仅拥有必要 SES 权限的 API 密钥；发信地域、发信地址和模板须属于同一可用配置。

```dotenv
EMAIL_MODE=tencent
EMAIL_CODE_SECRET=至少32位随机密钥
TENCENT_SECRET_ID=你的密钥ID
TENCENT_SECRET_KEY=你的密钥Key
TENCENT_SES_FROM=已验证的发信地址
TENCENT_SES_TEMPLATE_ID=已审核的数字模板ID
TENCENT_SES_REGION=ap-guangzhou
```

生产启动强制要求腾讯云邮件、32 位以上验证码 HMAC 密钥及 Secure Cookie，不会回退到本地测试模式。密钥不要提交 Git、截图或发到聊天。验证码使用加密随机数、服务端 HMAC 存储、5 分钟有效；同一邮箱最短 60 秒间隔，24 小时最多 10 次，连续错误最多 5 次。进程内 IP 限流是单实例基础保护，重启会重置；反向代理还需配置适当限流与费用监控。日志勿记录正式验证码或密钥。

## 1Panel / 腾讯云部署准备（尚未实际部署）

目标 Linux 服务器需要 Docker、Docker Compose、稳定域名、HTTPS 与相应备案。将本目录上传服务器，排除 `node_modules`、`.local-db`、`.local-test-db`、`.env`。服务器项目目录创建仅管理员可读的 `.env`：

```dotenv
POSTGRES_PASSWORD=随机十六进制密码
COOKIE_SECURE=true
EMAIL_CODE_SECRET=另一组随机密钥至少32位
TENCENT_SECRET_ID=你的密钥ID
TENCENT_SECRET_KEY=你的密钥Key
TENCENT_SES_FROM=已验证的发信地址
TENCENT_SES_TEMPLATE_ID=已审核的数字模板ID
TENCENT_SES_REGION=ap-guangzhou
```

在 Linux 中可运行 `openssl rand -hex 24` 生成密码与验证码密钥。`docker compose up -d --build` 或在 1Panel Compose 项目中使用 `compose.yaml`。数据库在持久卷中，应用仅绑定宿主机 `127.0.0.1:3000`；不对公网开放数据库或应用端口。修改 PostgreSQL 初始化密码后不是直接改 `.env` 就能更改已创建的数据库密码，需要同步安全地修改数据库用户凭据。

配置 HTTPS 代理到宿主机 127.0.0.1:3000 并保留 Host。注意 1Panel 的 OpenResty 可能运行于容器中，容器内 127.0.0.1 不是宿主机：需确认其使用宿主机网络，或由管理员配置受控共享网络；不得通过直接公开数据库端口绕过。腾讯云防火墙开放必要 80/443；管理面板和 SSH 限制受信任来源。安装证书并监控续期。

首次部署后先限定访问范围，真实联调邮箱登录、双小朋友、积分/库存并发、备份恢复及实际 iPad；再考虑开放。此前没有在真实 1Panel、标准 PostgreSQL Docker、云邮件或 iPad/微信内置浏览器完成验收，因此不能视为已经发布或经过生产验收。需定期把数据库一致性备份保存到服务器之外并验证恢复；Docker 卷不等于备份。在 Linux 可按实际环境使用 `docker compose exec -T db pg_dump -U study -Fc study > study-backup.dump`，加密后传到独立位置。恢复前确认目标，避免覆盖。

## 架构与边界

服务端每个家庭保存版本化 JSONB 快照及 revision；小朋友和商品有稳定 ID，写入行锁事务并通过 operationId 防止同一请求重复执行。家长账号对应邮箱，登录后只访问对应家庭；所有操作服务端校验归属。任务、积分、打卡及兑换业务在服务端处理。多设备冲突先刷新重试，不支持离线自动合并。

当前没有多家长共同管理同一家庭、孩子账户、跨家庭转移、找回/换绑邮箱、删除小朋友或账号、云上传图片、多租户运营后台等功能。资料按最小化收集，家长需妥善保护邮箱和账号。单 JSONB 家庭快照适合小规模自用；公开大规模服务前应评估关系表、数据库迁移、长期备份、监控、登录防刷、费用控制及安全审计。
