# 星星学习工作台：联网版需求、设计与部署交接

> 基线：2026-11-06，依据 `online/` 当前源码整理。本文是联网版的需求与交接入口；运行细节以同目录源码、`package-lock.json`、`compose.yaml` 和 `README.md` 为准。项目代码与数据库备份须另行保存：文档不能替代源码、实际密钥或运行数据。

## 1. 产品目标与范围

给家庭中的小朋友提供简洁、明亮、易触摸的学习工作台。家长设置学习任务和兑换商品，小朋友完成任务、每日打卡赚取积分，使用自己的积分兑换奖励。适配电脑、手机和 iPad 浏览器，目标包括微信内置浏览器；这些设备的最终效果需要真机验收。计划部署到腾讯云，通过固定 HTTPS 网址访问。

当前方案使用 React/Vite 前端、Node.js/Express 后端和 PostgreSQL 数据库；本地开发可使用 PGlite 持久化数据库。家长使用邮箱验证码登录，孩子不需要账号；一个家庭可有多个孩子。当前未部署到云服务器，不能把准备好的 Docker 配置视为已完成云端验收。

## 2. 家庭、账号与使用流程

- 一个已验证邮箱对应一个家长账号和家庭。邮箱去除首尾空格并统一小写；首次验证码验证成功后创建空家庭。不同家庭的数据隔离。
- 使用六位邮箱验证码，不提供手机号、短信或密码登录。验证码 5 分钟有效、只能成功使用一次，同一邮箱发送间隔至少 60 秒、24 小时窗口最多 10 次，每个验证码最多尝试 5 次。
- 登录会话有效期 7 天；登录 Cookie 为 HttpOnly、SameSite=Strict，生产设置 Secure。退出后服务端删除相应会话。
- 无孩子时展示创建页；一名孩子自动进入；多名孩子重新登录后先选择。工作台支持切换、新增，最多 20 名。
- 创建孩子时昵称必填，年级、年龄和性别选填；可修改资料。界面主题可单独选择薰衣草、薄荷绿、阳光黄、莓果粉，不依据性别自动限制主题。
- 家长和孩子使用同一已登录会话，家长管理页没有独立的家长身份验证或强制口令；当前不是多角色权限系统。家庭中的其他人若能操作该会话，也能进入家长管理。
- 孩子各自拥有资料、任务、完成记录、打卡、积分流水和兑换记录；家庭共用一套商品和库存。家长在当前孩子工作台处理其任务及兑换。

## 3. 功能需求与业务规则

### 3.1 工作台与资料

首页展示昵称、日期、可用积分、今日任务及进度、本周打卡、连续天数、可兑换商品和待兑现奖励。余额为负时显示需补回分数，可用积分显示为 0，不允许继续兑换。界面需清晰的状态、错误提示、足够大的文字与点击区域；减少动画和键盘可操作性需按实际设备验证。

资料保存昵称、年级、年龄、性别和主题；每项为字符串，主题为四种枚举之一。创建昵称需非空且不超过 40 字符；目前资料编辑校验允许空昵称，显示时使用默认称呼。年龄目前是文本字段，非出生日期或强制数字。各孩子主题彼此独立。

### 3.2 任务

- 添加、编辑、归档/恢复和软删除；名称去空格后非空、最长 80 字符。首页快捷添加默认创建一次性任务，支持表单回车提交；家长管理可选择一次性、每天或每周指定日期。
- 今天展示已创建、未删除、未归档，且符合今天周期的任务。已完成任务仍展示，显示弱化和删除线，可以撤销；空列表有提示。
- 一次性任务只对应一个有效完成状态；周期任务每个自然日独立完成。每天和每周任务只能在符合日期的今天操作。
- 完成获得 10 分，撤销扣回 10 分，再次完成重新获得 10 分。每次状态变化追加积分流水，避免同一有效完成重复记分。
- 归档和软删除保留历史及历史积分；已有完成记录的任务不能更改重复类型，可新建任务；删除有确认提示。每周指定日期可以修改。

### 3.3 打卡与日期

- 显示周一至周日，可查看历史周；仅今天可以打卡或取消，不支持补签。用星星/云显示打卡状态。
- 业务上的今天由服务端 `APP_TIMEZONE` 计算，默认 `Asia/Shanghai`，不是分别按各设备时区计算；需要正确服务器时间。日期用 `YYYY-MM-DD` 表达。
- 第一日打卡无积分，从与上一自然日连续的每一天起奖励 5 分。取消打卡时按实际连续相邻日期重新计算总奖励并追加差额流水，不因反复操作重复获得积分。
- 连续天数：今天已打卡从今天往前算；否则从昨天往前算；若昨天也没有则为 0。跨周、月、年按自然日相邻计算。

### 3.4 积分与流水

余额等于该孩子全部积分流水的 `amount` 之和；包括完成 +10、撤销 -10、连续打卡调整、兑换扣分、取消兑换退款。流水记录 ID、发生时间、类型、关联 ID、分值和说明；任务和兑换操作保留发生时说明/名称。允许负余额，已兑现奖励不倒扣。

### 3.5 家庭商品与兑换

- 家长可新增、编辑、上架、下架和软删除共享商品。名称非空最长 80 字符；兑换积分为 1–1,000,000 的整数；库存为空表示不限量，否则为 0–1,000,000 的整数；说明最长 120 字符。
- 商店只显示上架且未删除商品；显示价格、说明及库存，库存为零或积分不足时不可兑换。兑换前显示商品、价格、兑换后余额并请求确认。
- 兑换成功后同时扣除当前孩子积分、扣减有限库存并创建待兑现记录；记录保存商品名称和价格快照。数据库事务与家庭状态行锁用于保障扣分和共享库存的一致性。
- 家长可将待兑现记录设为已兑现，或取消待兑现并按原价格退款。兑换时为有限库存且该商品当前仍为有限库存时，取消恢复一份；商品现在为不限量则保持不限量。已兑现不能直接取消。
- 商品编辑、上下架或软删除不改变过去的兑换名称和价格。共享库存被一个孩子兑换后，其他孩子看到更新后的数量，但积分和兑换记录不共享。

### 3.6 数据、备份与同步

- 业务以服务端数据库为准，多设备登录同一邮箱后访问同一家庭；无离线操作队列或自动合并能力。首页在可见时定期检查最新数据；不同设备发生修订冲突时提示并刷新后重试。
- 家长管理提供整个家庭的 JSON 导出/导入：包含所有孩子与共享商品，不包含邮箱账号、验证码或会话。导入前确认，会替换当前家庭业务数据；文件最多 5 MB；无效数据不能覆盖现有数据。
- 旧版单孩子备份与账号密码迁移代码仍在，但用户确认当前无旧数据，首次部署不需要迁移。迁移不是上线前置条件。
- 浏览器与服务端出错时应给用户提示。生产数据库必须定期异地备份并验证恢复；Docker 卷不是备份。

## 4. 技术设计与源码地图

```text
浏览器：React / Vite（构建后静态资源）
       │ 同源 HTTPS；Cookie 会话、JSON API
       ▼
1Panel/OpenResty 反向代理 → Node.js / Express 应用
       │                                      │
       ├─ 事务、版本检查、业务规则             └─ 腾讯云邮件推送 API
       ▼
PostgreSQL 16（Docker 持久卷；不对公网开放）
```

生产由同一个 Node 服务提供 `dist/` 静态资源和 `/api`，前后端逻辑分离、同源部署，不需要分别公开两个服务。开发依赖 Node.js 22 或 24、npm；准确依赖由 `package-lock.json` 锁定。

| 相对 `online/` 的路径 | 职责 |
| --- | --- |
| `src/main.jsx`、`src/style.css` | React 页面、交互、展示和样式 |
| `server/index.js` | 环境检查、数据库连接、静态文件及服务启动 |
| `server/app.js` | 初始化表、API、邮箱认证、事务、会话与家庭隔离 |
| `server/email.js` | 本地控制台验证码与腾讯云 SES API 适配器 |
| `server/domain.js` | 任务、打卡、积分、商品、兑换及一致性校验 |
| `server/family.js` | 家庭、孩子、共享商品与家庭备份 |
| `server/local-db.js` | 本机 PGlite 及本地事务适配 |
| `tests/core.test.js` | 业务、认证与家庭隔离测试 |
| `Dockerfile`、`compose.yaml` | 生产镜像与应用/数据库编排 |
| `.env.example`、`README.md` | 本地变量示例及运行说明 |

### 4.1 当前数据设计

`accounts` 保存家长 ID、以 `email:` 开头的邮箱用户名及兼容旧版字段；`sessions` 保存令牌哈希和过期时间；`email_codes` 保存验证码 HMAC、有效期、尝试与发送计数；`family_state` 每个家庭一条 JSONB 状态和 `revision`；`operations` 记录请求幂等 ID。家庭快照 `schemaVersion: 2`，包含 `children` 和共享 `products`；每个孩子状态 `version: 1` 包含 `profile`、`tasks`、`completions`、`checkins`、`ledger`、`redemptions` 等。

写入使用事务、家庭记录行锁、`revision` 乐观并发检查与 `operationId` 去重。所有业务变更在服务端计算并校验后保存；切换前端框架时应保留这些语义。单家庭 JSONB 适合当前家庭自用规模；公开、多家庭大规模运营前需重新评估关系表、迁移、容量与性能。

### 4.2 API 契约概览

所有路径同源，变更请求发送 JSON 并带 `X-App-Request: study`；服务端检查 Origin（有提供时）与 Host 相符。认证依赖 `study_session` Cookie。

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/status` | 返回 `emailMode`，用于提示本地测试模式 |
| `POST /api/email/send` | `{email}`，发送六位码，成功返回 `{ok,retryAfter}` |
| `POST /api/email/login` | `{email,code}`，验证、创建/查找家庭并设置 Cookie |
| `POST /api/logout` | 注销当前会话 |
| `GET /api/state?childId=...` | 家庭孩子列表；选定孩子时返回状态、积分、revision 和 today |
| `GET /api/export` | 导出整个家庭快照 |
| `POST /api/action` | `{action,payload,childId,revision,operationId}`；409 代表版本冲突 |
| `POST /api/migrate-legacy` | 旧密码账号兼容迁移；新部署无需使用 |

`action` 当前包括 `child.add`、`profile`、`task.save/toggle/archive/delete`、`checkin.toggle`、`product.save/active/delete`、`redeem`、`redemption.fulfill/cancel`、`family.import` 和旧版 `import`。校验细节以源码为准。操作幂等依赖客户端对同一请求复用相同 `operationId`；不同 ID 的重复操作属于不同请求，不能声称所有重复点击都自动幂等。

### 4.3 安全边界

验证码由安全随机数生成，仅存服务端 HMAC；生产须配置独立的至少 32 字符随机 `EMAIL_CODE_SECRET`。进程内 IP 限流每 15 分钟 40 次，是单实例基础保护，重启丢失；代理环境下需正确设计真实来源识别、网关限流和费用监控。邮件发送失败返回错误；成功仅表示接口受理，不保证送达。

后端 JSON 大小限制 5 MB；状态修改进行来源与自定义请求头检查；Session 保存哈希。当前没有邮箱换绑/注销、多家长协作、孩子独立账号、家长管理二次验证、自动备份与运维告警。正式公开给其他家庭前还需进行隐私、鉴权、安全审计、反刷、备份和恢复评估。

## 5. 换电脑后的交接与本地运行

### 5.1 需要带走什么

1. 安全复制整个 `study-space/online/` 项目，包括源码、`package.json`、`package-lock.json`、`Dockerfile`、`compose.yaml`、本文和 README。上层 `study-space/` 中旧单文件项目属于历史版本，不是联网版运行入口。
2. `node_modules/`、`dist/` 可在新电脑重新生成，通常不必传输。若有需要保留的本地测试数据，停止服务后单独备份 `.local-db/`；其他机器不会自动拥有该数据。`.env`、私钥、云密钥不放进普通压缩包或公开仓库，按安全方式另行配置。
3. 本文无法恢复未打包的源码、数据库、证书或凭据。旧聊天中提到的压缩包可能只存在原电脑上；先通过网盘、U 盘或其他方式传输并确认可解压。用户已确认当前无需要迁移的旧业务数据。

### 5.2 Windows / macOS 本地运行

安装 Node.js 22 或 24 后，在新机器进入解压得到的 `online` 目录：

```bash
npm ci
npm run build
npm test
npm run local
```

浏览器打开 `http://127.0.0.1:3000/`。输入任意符合格式的测试邮箱并获取验证码；**本地默认不发真实邮件**，验证码只显示在运行服务的终端。测试完成 `Ctrl+C` 停止，数据库默认位于 `online/.local-db/`。若端口被旧服务占用，先停止旧服务再启动。配置 `.env` 时检查没有残留生产设置；生产密钥不要用于本地演示。

`npm test` 使用 pg-mem 和本地 PGlite；`npm run build` 生成 `dist/`。若修改源码，需重新构建再使用 `npm run local` 查看；`npm run dev` 需要 PostgreSQL `DATABASE_URL`，不是上述 PGlite 启动方式。

## 6. 腾讯云 / 1Panel 部署方案与操作

### 6.1 现状和前置条件

- 已购买腾讯云轻量应用服务器，地域上海，1Panel 镜像；实例 ID、公网 IP 和 SSH 用户以腾讯云控制台实际信息为准。
- 曾在服务器 `/root/.ssh/authorized_keys` 添加旧电脑的专用公钥；当时本机无法连接 22 端口，尚未验证 SSH。新电脑建议生成独立 SSH 密钥并通过云控制台安全添加公钥；首次连接核对服务器主机指纹，不复制或发送私钥。确认防火墙、实际 SSH 端口和可信来源。
- 需确认服务器资源、已运行服务和端口，避免覆盖现有内容。准备域名及 DNS、HTTPS 证书；中国大陆服务器域名访问是否需要备案，按实际服务与腾讯云/主管部门要求确认。当前域名和备案状态未确认。
- 腾讯云邮件推送需先开通、完成验证；邮件域名及网站域名可以按实际配置决定。创建并验证发信域名、DNS、发信地址以及包含 `{{code}}` 的可用模板，准备该模板数字 ID 和最小权限 API 凭据。腾讯云实际审核及可用地域以控制台为准。不要在聊天、仓库或截图泄露密钥。
- 还需 Docker 和 Docker Compose；1Panel 的版本、OpenResty 网络与实际配置应先确认。资源为 2 核 2 GB，构建镜像可能紧张，应检查内存及磁盘，不擅自关闭其他服务。

### 6.2 上传与配置

1. 将 `online/` 复制到服务器的独立项目目录，例如 `/opt/study-workbench`；排除 `node_modules`、`dist`、本地数据库、`.env`、`.git`。先确认目录是否已存在，避免覆盖。
2. 在项目目录创建仅管理员可读的 `.env`，内容示意如下，填入实际值；数据库密码使用 URL 安全的随机十六进制值，避免连接字符串特殊字符问题。生成两个互不相同的随机密钥可各自执行 `openssl rand -hex 32`。不要把真实输出粘贴到聊天。

```dotenv
POSTGRES_PASSWORD=替换为随机十六进制数据库密码
COOKIE_SECURE=true
EMAIL_CODE_SECRET=替换为另一组至少32字符的随机密钥
TENCENT_SECRET_ID=实际密钥ID
TENCENT_SECRET_KEY=实际密钥Key
TENCENT_SES_FROM=已验证发信地址
TENCENT_SES_TEMPLATE_ID=已审核模板数字ID
TENCENT_SES_REGION=ap-guangzhou
```

3. 保存后设置 `chmod 600 .env`。`compose.yaml` 已将生产 `EMAIL_MODE` 固定为 `tencent`，配置缺失时不应回退到控制台验证码。`COOKIE_SECURE=true` 要求用户使用 HTTPS 登录。
4. 审核 Compose 设置、环境和当前服务器后，在该目录执行：

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
```

不要将完整 `docker compose config` 输出发到聊天，因为它可能包含密钥。Compose 启动 PostgreSQL 16，`study_db` 为命名持久卷；应用默认仅绑定宿主机 `127.0.0.1:3000`。更换 `.env` 的数据库密码不会自动修改已有 PostgreSQL 用户密码，已有数据时应按数据库流程同步变更。不要运行会删除卷的数据清理命令。

### 6.3 反向代理与网络

在 1Panel 中创建独立网站，指向应用上游，保留原 Host，并配置域名、HTTPS 证书及自动续期。若 1Panel/OpenResty 与应用不在同一网络命名空间，**代理容器内的 `127.0.0.1` 不是宿主机**；需根据实际安装方式使用受控的宿主机网络或共享 Docker 网络，验证上游可达后再配置。不要为了方便把数据库端口暴露公网。

腾讯云防火墙仅开放必要的 80/443；SSH 与面板访问限制可信来源。不要随意更改或覆盖现有 1Panel 站点。部署后用 HTTPS 访问，检查邮件收取、Cookie、家庭隔离、双孩子、库存与积分；如果 DNS、证书或邮件服务未准备好，则部署不能视为完成。

### 6.4 备份、更新与排障

上线后制定定期数据库一致性备份、异地加密保存、恢复演练与密钥轮换。下面的命令在项目目录生成 PostgreSQL 自定义格式备份；先确认目的磁盘空间和目标目录，文件含家庭隐私数据：

```bash
docker compose exec -T db pg_dump -U study -Fc study > study-backup.dump
```
